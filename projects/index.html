Personal Comic Project

Kimia's Hands-On Guide to Magic

This comic is a passion project I've been doing on-and-off work on since mid-2025. The comic is a coming-of-age fantasy adventure story that follows a young rogue witch as she tries to find family, purpose, and a place she belongs. The story is meant to be pretty casual and personal, and is named after the protagonist's handsy powers. Haha, get it?

Below, you'll find my process notes, some drafts and ideations, and whatever else I've decided to throw in here. As I finish more chapters and pages, I'll throw them on this site, but it's kind of a pain to update so don't expect super regular upkeep. Peace.

About BEET

BEET is a hackathon project I worked on alongside some other friends. Among our team is a music guy and two code guys. I assumed the role of the asset and concept artist, so most of the assets you see in game were created by me. Due to time restraints, I didn't do any UI work, but we'll get around to that.

The game itself is the manifestation of a dream game idea my friend conjured up one day. We decided there was no better time than a hackathon to finally assemble a team and begin work on it. In this game, you play as a young traveller exploring a broken, sad world. The wildlife has been corrupted and music is gone.

There are two primary gameplay loops; a combat and platformer oriented one that takes place in a 2D sidescrolling environment, and an isometric town builder kind of like My Singing Monsters but with plants. For legal reasons, these are entirely distinct concepts.

For fun mini game

Poker Game

Poker Game is a tiny python game I created as an offshoot of a class assignment. Our final task was to create a card game using python, and our group chose Texas Hold'em Poker. I wasn't satisfied with what we presented, so in my own time, I created this.

You can think of Poker Game as a visual experiment. I wanted to see what I could accomplish using simple transforms and static sprites. The end result is something I'm actually pretty happy with. In terms of code, this project is really rough around the edges (I'm not the most competent coder, so most of this was vibe coded), but at the very least it serves as a neat visual reference for a future where I rebuild Poker Game with more robust architecture.

Development Notes

Visual Approach

As the sole developer of Poker Game (not counting codex), I had pretty much total control over how I wanted it to look and feel like. Personally, I really like when games don't try to hide the rough, sketchy parts of their art. This led me to approach the game almost like I'd approach making a painting.


Whenever a new screen or UI element needed to be made, I'd lay it out in a Procreate canvas with a screen size reference, and paint the scene, separating sprites into layers so I can export them later.

While I obviously can't use a fully painterly approach, this recontextualized the project from something wholly outside my depth to something I felt a lot more familiar with. This way, I was easily able to apply my knowledge of color, composition and emphasis to create an appealing UI and background.
